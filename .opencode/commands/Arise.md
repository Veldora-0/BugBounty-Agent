---
description: Build the Bug-Bounty agent's target-independent public methodology library
---

Run the BugBounty-Agent `/Arise` learning workflow using the existing `Bug-Bounty` primary agent and `knowledge-research` skill. Do not create or delegate to a subagent.

This command is not tied to a target or program. Its purpose is to find useful public vulnerability-disclosure methodology that is missing or thin in the agent's current skills and saved methodology library. Review the 18 installed skills and the existing library at `~/.config/opencode/bug-bounty-agent/knowledge/methodology.json` (or the active `OPENCODE_CONFIG_DIR` equivalent). Look across vulnerability families and research methods; prioritize practical, reproducible techniques, underrepresented areas, and meaningful variants rather than collecting target-specific reports or duplicates. GHDB may be used as a methodology reference for search-exposure classes, with its own official link.

Use an available read-only public research/search capability. Search only publicly disclosed bounty reports, public security research, standards, advisories, and reputable methodology references. Respect source terms and rate limits. Do not use private or undisclosed reports. A report does not establish that any other target is vulnerable.

For each useful, novel method, save only compact context and provenance: source URL, title, author or source attribution, publication date when available, vulnerability family, optional technology tags, and a concise methodology summary of at most 600 characters. Reports must be publicly disclosed; official public standards and methodology references may use `PUBLICLY_AVAILABLE`. Never save report bodies, screenshots, exploit dumps, credentials, target information, or copied long passages. Save the researcher-reviewed JSON array to a temporary file outside the repository, import it with `bb-arise --discoveries <local-json> --checked-source <host> --unchecked-source <host> --json`, passing source flags only when those checks actually happened, then remove the temporary file after a successful import. The CLI stores records in the global Bug-Bounty agent data directory, not a target workspace. The library is capped at 1,000 references; if it fills, stop and ask for curation rather than deleting entries automatically. If search is unavailable, explain that no new sources were checked and leave the library as-is.

The library is reusable across programs. When the researcher later asks to investigate an authorized target, first validate the selected program's scope and local coverage, then have `bb-plan` match saved methodology by vulnerability family and show the report link, attribution, and concise context with related recommendations. Open a linked public report on demand only when useful; adapt its method to the current in-scope surface and current program rules. Do not treat a report or a match as target evidence, authorization, or a reason to execute a test automatically.

`/Arise` and `bb-arise` do not send requests to targets or source websites; source discovery/rechecking happens only through the available read-only research capability. Do not send requests to targets, run scanners, test vulnerabilities, or submit reports in this learning workflow. Active target follow-up remains a separate, human-approved action through the existing scope, approval, dispatch, and budget gates. Keep methodology outside Git and target program directories.
