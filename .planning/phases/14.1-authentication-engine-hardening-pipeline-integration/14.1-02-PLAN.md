# Plan 14.1-02: Cross-Phase State Ingestion & Surface Discovery

## Objective
Implement robust, production-grade ingestion of actual multi-phase state files into `AuthenticationSurfaceDiscoverer` and `IdentityManager`. Ingest endpoints, forms, and cookies from `state/webapps.json`; API endpoints and authentication observations from `state/api.json`; routes and strings from `state/javascript.json`; hostnames and TLS SANs from `state/assets.json` and `state/recon.json`; principals and sessions from `state/authorization.json`; and multi-step workflows and transitions from `state/workflows.json`. Ensure ingestion strictly matches each state manager's actual serialized JSON structure (lists vs dictionaries) rather than assuming field names map directly, and guarantee graceful degradation without crashing on missing, empty, partial, or corrupted files.

## Read First
- `framework/authentication/discovery.py` (Current surface discovery logic)
- `framework/authentication/identity.py` (Current identity manager logic)
- `framework/webapp/state.py` (`WebAppStateManager`: serialized `"endpoints"`, `"forms"`, `"cookies"` as lists of dicts)
- `framework/api/state.py` (`ApiStateManager`: serialized `"endpoints"`, `"parameters"`, `"auth_observations"` as lists of dicts)
- `framework/javascript/state.py` (`JavaScriptStateManager`: serialized `"endpoints"`, `"routes"`, `"interesting_strings"` as lists of dicts)
- `framework/recon/state.py` (`ReconStateManager`: serialized `"http_services"`, `"tls_records"` with SANs, `"endpoints"` as lists of dicts)
- `framework/state/manager.py` (`StateManager`: `assets.json` dictionary format `{hostname: {...}}` and graph format `{"assets": {...}}`)
- `framework/authz/state.py` (`AuthorizationStateManager`: serialized `"principals"` and `"sessions"` as dictionaries keyed by ID)
- `framework/business_logic/state.py` (`WorkflowStateManager`: serialized `"workflows"` as dictionary of `{workflow_id: {...}}` containing `steps` and `transitions`)

## Context
Cross-phase state ingestion must reflect actual serialization schemas of earlier phases. The state managers use different serialization structures:
- `webapps.json`, `api.json`, `javascript.json`, and `recon.json` serialize collections as **lists of dicts** under top-level keys (`"endpoints": [...]`, `"forms": [...]`, `"auth_observations": [...]`).
- In contrast, `authorization.json` and `workflows.json` serialize collections as **dictionaries keyed by ID** (`"principals": {"user_a": {...}}`, `"workflows": {"wf_01": {...}}`).
- `assets.json` supports both graph format (`{"assets": {id: {...}}}`) and legacy map format (`{hostname: {...}}`).

The loader must inspect and safely deserialize each actual schema, normalize paths and methods, extract authentication surfaces and identity profiles, and remain completely resilient to empty, missing, partial, or malformed state files.
