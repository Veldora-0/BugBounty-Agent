# Plan 14.1-03: Operational Coverage & Hardened Validation Heuristics

## Objective
Implement evidence-backed validation and operational coverage across all 14 declared vulnerability families in `AuthenticationFindingFamily`. For all 11 operational families, implement the end-to-end hypothesis generation path, policy checks, validators, evidence requirements, and false-positive elimination. For the 3 observation-only families, verify that incomplete evidence cannot automatically escalate into confirmed vulnerabilities. Eliminate status-code-only false positives (such as generic 200 OK login forms and WAF challenges) by requiring empirical baseline differentials (anonymous vs authenticated). Treat timing differences and response text variations as signals, not standalone proof of account enumeration. Enforce that state-mutating actions strictly require in-scope targets, safe policies, researcher-controlled test accounts, and operator approval (`--approve`), while guaranteeing that approval never overrides scope restrictions.

## Context
A primary reason bug bounty reports get rejected as false positives is relying on HTTP status codes alone (e.g., flagging 200 OK without inspecting whether the response is a login form or WAF page), or treating raw timing variations as proof of account enumeration. 

In this plan, we enforce strict verification standards across all 14 families:
1. Operational Families:
   - `AUTHENTICATION_BYPASS`: Protected resource accessible anonymously; response differs from anonymous baseline and matches authenticated profile.
   - `PRE_AUTH_PRIVILEGE_EXPOSURE`: Pre-auth route exposes actions/data intended only for authenticated users.
   - `SESSION_FIXATION`: Pre-session identifier accepted post-auth and provides authenticated privileges.
   - `SESSION_NOT_INVALIDATED`: Post-logout/password-change reuse successfully accesses protected resource with old session token.
   - `PASSWORD_RESET_TOKEN_REUSE`: Consumed reset token successfully resets password a second time on researcher-controlled test account.
   - `PASSWORD_RESET_STATE_CONFUSION`: Parameter tampering or out-of-order execution allows resetting arbitrary account.
   - `ACCOUNT_ENUMERATION`: Timing differences and text differences are signals only; requires repeatable differential evidence across multiple trials under stable conditions.
   - `MFA_BYPASS`: Bypassing secondary factor grants access to an endpoint/action strictly requiring verified MFA.
   - `MFA_STATE_CONFUSION`: Manipulating MFA session state transitions skips secondary verification.
   - `REFRESH_TOKEN_REUSE`: Replaying an already rotated refresh token successfully yields new access tokens.
   - `AUTHENTICATION_STATE_INCONSISTENCY`: Divergent authentication state enforcement across application boundaries/services.
2. Observation-Only Families:
   - `SESSION_NOT_ROTATED`: Missing session ID rotation across privilege change without session fixation remains an observation.
   - `TOKEN_TRANSPORT_EXPOSURE`: Token in URL query params or headers without demonstrated leakage remains an observation.
   - `AUTHENTICATION_CONFIGURATION_WEAKNESS`: Missing cookie security flags (`Secure`, `HttpOnly`, `SameSite`) or JWT structural concerns without exploitable server acceptance remain observations.

Furthermore:
- Approval never overrides scope: If a target evaluates to `OUT_OF_SCOPE` or `AMBIGUOUS`, `--approve` has no effect; active validation is aborted immediately.
