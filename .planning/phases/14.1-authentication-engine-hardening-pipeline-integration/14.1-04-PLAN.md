# Plan 14.1-04: Deterministic Fingerprinting, Deduplication, Resume & Evidence Model

## Objective
Implement deterministic SHA-256 test fingerprinting and state indexing into `state/tests.json` using the exact signatures of `generate_test_fingerprint`, `StateManager.has_test_run`, and `StateManager.record_test`, ensuring deduplication does not suppress legitimate retesting when context (principal, credential state) changes. Add `--resume` support to recover previously evaluated hypotheses and findings from `state/authentication.json`. Enforce strict sensitive credential redaction across all stored evidence. Integrate finding persistence with the canonical `Finding` schema and `FindingLifecycle` state machine, ensuring candidates only become `FindingLifecycle.VALIDATED` when backed by successful family-specific validation, sufficient sanitized evidence, and false-positive elimination; otherwise preserving `CANDIDATE`, `OBSERVATION`, `INFORMATIONAL`, or `REJECTED` states.

## Context
In the framework's architecture, findings are governed by a strict lifecycle:
`OBSERVATION -> HYPOTHESIS -> CANDIDATE -> VALIDATED / REJECTED / DUPLICATE / INFORMATIONAL`.
A finding candidate must **never** be marked as `VALIDATED` simply because it was converted into a `Finding` object. A finding is only marked `VALIDATED` if:
1. It has undergone active operational testing for its specific family.
2. It exhibits empirical baseline differential proof (e.g. authenticated vs anonymous differential).
3. It has passed `AuthenticationFalsePositiveClassifier` without triggering login form or WAF heuristics.
4. It contains sanitized evidence records with cryptographic SHA-256 digests.
If a finding represents an observation-only family (such as `AUTHENTICATION_CONFIGURATION_WEAKNESS` or `SESSION_NOT_ROTATED`) or has unverified impact, its lifecycle state must remain `INFORMATIONAL`, `OBSERVATION`, or `CANDIDATE`.

Additionally, test deduplication in `state/tests.json` must be context-aware: while identical redundant probes under the same identity must be skipped, testing an endpoint under a different principal or after credential mutation must not be suppressed.
