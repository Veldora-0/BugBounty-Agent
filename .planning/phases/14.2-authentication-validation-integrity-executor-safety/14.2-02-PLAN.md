# Plan 14.2-02: State Ingestion Resiliency, Deterministic Fingerprinting & Evidence Redaction

## Objective
Harden state loading, hypothesis generation, evidence sanitization, and cross-phase state ingestion. Implement deterministic, context-aware hypothesis IDs to make test deduplication and `--resume` reliable across runs; eliminate silent exception swallowing during state loading; enforce comprehensive credential sanitization across query parameters, cookies, authorization headers, and nested JSON structures; clarify that cryptographic hashes represent provenance metadata rather than vulnerability proof; and harden schema adapters for all 7 upstream phase state files (`webapps.json`, `api.json`, `javascript.json`, `assets.json`, `recon.json`, `authorization.json`, `workflows.json`).

## Read First
- `framework/authentication/hypotheses.py` (Hypothesis formulation and ID generation)
- `framework/authentication/storage.py` (State persistence and loading)
- `framework/authentication/evidence.py` (Evidence recording, sanitization, hashing)
- `framework/authentication/discovery.py` (Multi-phase state ingestion)
- `framework/authentication/identity.py` (Identity profile management)
- `framework/authentication/models.py` (Candidate-to-native finding conversion)
- `framework/state/manager.py` (Core framework state and test recording)

## Context
Code inspection identified several integrity vulnerabilities:
1. `AuthenticationHypothesisEngine` embedded random UUIDs (`uuid.uuid4().hex[:6]`) into every hypothesis ID. This broke resume capabilities, because loaded hypotheses from previous runs never matched the newly formulated hypotheses on endpoint, family, and principal.
2. `AuthenticationStateManager.load_state()` wrapped parsing in a bare `except Exception:` and silently returned empty collections, treating corrupted JSON as empty state. This silently destroyed deduplication records and allowed duplicate probes.
3. Credential sanitization in `AuthenticationEvidenceManager` handled regex replacements on plain text strings, but did not handle nested JSON fields, Basic auth tokens, or custom headers in dictionary structures before serialization.
4. Schema parsing in `discovery.py` needed defensive parsing against diverse schema versions (list-of-dicts vs dict-of-dicts) across upstream phases.

<task id="14.2-02-T1">
<read_first>

- framework/authentication/models.py

<action>
Implement deterministic, context-aware hypothesis ID and fingerprint generation:
1. Remove all `uuid.uuid4()` calls from `AuthenticationHypothesisEngine`.
2. Generate deterministic hypothesis IDs based on canonical SHA-256 hashes:
   ```python
   def generate_hypothesis_id(family: str, endpoint: str, principal: str, required_state: str) -> str:
       raw = f"{family.upper()}|{endpoint.strip()}|{principal.strip()}|{required_state.upper()}"
       digest = hashlib.sha256(raw.encode("utf-8")).hexdigest()[:10]
       return f"HYP-{family[:8]}-{digest}"
   ```
3. Ensure context-awareness:
   - Include `endpoint`, `family`, `principal`, and `required_state`.
   - Distinct principals or distinct roles testing the same endpoint generate distinct hypothesis IDs, allowing legitimate retesting under different security contexts while deduplicating identical probes.
4. Update `AuthenticationSecurityEngine.load_existing_state()` to match hypotheses deterministically using `hypothesis_id`.
</action>
<acceptance_criteria>
- Re-running hypothesis generation on the same input produces identical hypothesis IDs.
- Two different identities (e.g. `user_a` vs `user_b`) generate distinct hypothesis IDs.
- Loading state and re-formulating hypotheses merges existing validation statuses without duplicate entries.
</acceptance_criteria>

<read_first>

- framework/authentication/models.py

<action>
Refactor state persistence and error handling in `AuthenticationStateManager`:
1. Distinguish missing files from corrupted files in `load_state()`:
   - If `state/authentication.json` does not exist: Return empty collections (clean initialization).
   - If `state/authentication.json` exists but cannot be parsed (JSON syntax error, truncated file, invalid schema):
     - DO NOT silently return empty collections.
     - Log an explicit error to `sys.stderr`.
     - Raise `CorruptedStateError` or return a structured state with error metadata and `is_corrupted: True`, alerting the engine.
     - Provide backup copy (`state/authentication.json.corrupt.<timestamp>`) before overwriting.
2. In `save_state()`, ensure atomic write via tempfile, flush, `os.fsync`, and `os.replace`.
3. In `models.py` (`to_native_finding`):
   - Only assign `FindingLifecycle.VALIDATED` if `is_validated == True` AND family is an operational vulnerability family AND required differential evidence exists.
   - Assign `FindingLifecycle.INFORMATIONAL` to observation-only families (`SESSION_NOT_ROTATED`, `TOKEN_TRANSPORT_EXPOSURE`, `AUTHENTICATION_CONFIGURATION_WEAKNESS`).
   - Assign `FindingLifecycle.CANDIDATE` to unverified or preliminary hypotheses.
4. Surface persistence failures:
   - In `engine.py`, remove bare `except Exception: pass` around `self.state_manager.save_finding(native_f)`.
   - If writing to `state/findings.json` fails, log the exception explicitly to `sys.stderr`, mark the candidate with `persistence_error`, and surface the error to the operator rather than silently discarding findings.
</action>
<acceptance_criteria>
- Corrupted JSON in `state/authentication.json` does not silently pass as clean state.
- Observation-only families are never saved with `FindingLifecycle.VALIDATED`.
- Finding persistence failures in `save_finding()` are logged and surfaced, never silently swallowed with `pass`.
- Validated findings are saved with full provenance evidence and correct lifecycle states.
</acceptance_criteria>

3. Cryptographic hash provenance:

   - Explicitly document that evidence digests do not constitute proof of vulnerability.

## Verification Strategy
- **Deduplication & Resume Tests**:
  - Test deterministic hypothesis generation: verify identical outputs across multiple invocations.
  - Test resume capability: serialize state, re-instantiate engine with `--resume`, verify hypotheses retain prior statuses.
- **Redaction Verification**:
  - Test query parameters, JSON payloads, headers, cookies, and nested structures against all redaction tokens.
- **Cross-Phase Schema Compatibility**:
  - Test loading empty, partial, list-based, and dict-based JSON schemas for all 7 state files.
